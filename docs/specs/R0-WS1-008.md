# R0-WS1-008 — shared Terraform modules

## What this story built

A repository holding reusable Terraform modules, composed by `platform-infra` which owns
the environments and the state. One module so far — `network` — tagged `v0.1.0` and
consumed by the dev environment through a pinned git ref.

## Why the split, and why pinning is the point

A module and an environment change for different reasons and at different rates. An
environment changes when *this* deployment needs something; a module changes when the
shape of the thing changes everywhere. Together, every environment edit shares a history
with every design change and there is no version to pin.

Pinning is what makes the separation worth having. `platform-infra` references a tag, so a
change here reaches an environment when someone bumps the ref and a plan is reviewed — not
the next time anyone runs `apply`. For a module that defines a firewall, that difference
is the whole safety story.

## The three rules

Each is written in the README next to the failure it prevents.

**A module reads nothing.** No data sources against a live project, no remote state
lookups. A module that reads the world cannot be planned without that world existing,
which makes it untestable and makes `terraform plan` in CI depend on whichever environment
happens to be up. The proof is that `make check` validates with no credentials and no
cloud project — that is not a convenience, it is the test.

**No provider blocks.** A provider inside a module cannot be overridden and pins every
consumer to one project and region.

**Tag every change.** Consumers pin, so an untagged change reaches nobody — which is
correct, and also means forgetting to tag looks exactly like doing nothing.

## Private, unlike platform-workflows

`platform-workflows` is public because a Free organisation cannot share reusable workflows
from a private repository. The same reasoning does not extend here: workflow files are
build instructions, and these modules are the network topology — CIDRs, zone boundaries,
which subnet may reach which. For a platform whose security design is built on network
zones (HLD §10.2), that is a map.

The cost is real and landed immediately: Terraform's git fetch needs a credential, and
GitHub federation does not exist. Deploy keys would have been scriptable and are disabled
across the organisation — a deliberate hardening that agrees with this platform's own rule
about long-lived credentials. The narrowest remaining option is a fine-grained token
scoped to one repository and `Contents: Read-only`, which is what `R0-WS1-006` uses.

## What this deliberately does not do

Four of the five modules named in the README do not exist: `gke`, `data`,
`observability`, `temporal`. They are listed so the shape is visible before it is built,
and so a story that invents a sixth has to explain why.

## Verification

`make check` formats and validates every module with no credentials. `platform-infra`'s
dev environment fetches `network` at `v0.1.0` and plans against it: **29 to add, 0 to
change, 0 to destroy**.

## Definition of Done

Met, except **Deployed** — nothing has been applied from these modules yet, and applying
is CI's job (`R0-WS1-001`). `DEVELOPMENT.md` §3, backstopped by `R0-ALL-003`.
